# ข้อกำหนด V3: แยกระบบตัดสินใจออกจากระบบเก็บข้อมูล

ข้อตกลงผู้ใช้: 20 ตุลาคม 2026 เวลา 20:00 น. ประเทศไทย
สถานะ: ข้อกำหนดประกอบชุดติดตั้ง V3 ที่พัฒนาและทดสอบออฟไลน์แล้ว ยังไม่ได้ติดตั้งบน VPS จริง

## ข้อควรระวังเป็นพิเศษ

ข้อมูลเพื่อวิเคราะห์ต้องไม่กลายเป็นเงื่อนไขตัดสินใจโดยไม่ตั้งใจ ห้ามให้การติดตามหลัง SL เปลี่ยนฝั่ง เปิดหรือบล็อกไม้ เปลี่ยน TP/SL เพิ่ม cooldown ปรับคะแนน หรือปรับพารามิเตอร์อัตโนมัติ

## ขอบเขต V3 ที่ตกลง

- ใช้ V2 เป็นฐาน เพิ่มการจัดการ setup ปฏิกิริยาค้าง โดยทดสอบผลกระทบก่อนใช้จริง
- บันทึกเหตุผลของขาราคาเป็นข้อมูลอธิบาย แยกจากค่าที่ใช้ตัดสินใจ การบันทึกไม่ใช่สิทธิ์เพิ่มกฎเลือกฝั่งใหม่
- เพิ่มการติดตามหลัง SL จนถึงเวลาปิดแท่ง M5 ที่เกิด SL เป็นงานเก็บข้อมูลเท่านั้น
- ข้อตกลงเพิ่มเติม 20:32 น.: ใช้ max_chase_atr=0.40 ร่วมกับแก้ setup ค้าง; ไม่เพิ่ม ER, ไม่เปลี่ยนกฎเลือกโครงสร้างฝั่งใหม่หรือกฎ SL

## 1. ระบบตัดสินใจ (decision)

- รับเฉพาะข้อมูลตลาดที่มีอยู่ ณ ขณะนั้น การตั้งค่าที่อนุมัติ และสถานะการตัดสินใจของตนเอง
- เป็นส่วนเดียวที่มีสิทธิ์เปลี่ยน setup/position/cooldown และตัดสินใจเข้าออก
- การแก้ setup ค้างเป็นการเปลี่ยนพฤติกรรมในส่วนนี้ ต้องแยกทดสอบจากงานบันทึก
- ห้ามอ่านผล post-SL, สถิติการวิเคราะห์ หรือข้อมูลที่เกิดหลังจุดตัดสินใจเป็น input
- ห้าม import โมดูลวิเคราะห์เพื่อเรียกย้อนกลับเข้าตัวตัดสินใจ

## 2. ระบบบันทึกเหตุผล (decision audit)

- รับสำเนาผลและเหตุผลจาก decision เช่น ฝั่งที่เลือก เหตุผล ระดับที่ใช้อ้างอิง เวลา และเวอร์ชันกฎ
- ระบุให้ชัดว่าอะไรเป็น input ที่ decision ใช้จริง อะไรเป็นคำอธิบายหรือสมมติฐานเพื่อวิจัย
- ห้ามแก้ state/config ของ decision และห้ามเรียก decision ซ้ำเพื่อสร้างคำสั่งใหม่

## 3. ระบบติดตามหลัง SL (post-SL research)

- รับเหตุการณ์ SL ที่บันทึกแล้ว พร้อมสำเนา trade เดิมและราคาตลาดถัดมา
- เก็บสถานะและผลแยกจาก active setup/position เช่น post_sl_observers และ post_sl_observations
- ผูกด้วย trade_id และ rule_version; ห้ามเขียนทับ trade เดิมหรือเปลี่ยนผล SL เป็น TP
- ติดตามแต่ละไม้เป็นอิสระ การเปิดไม้ถัดไปไม่ทำให้ข้อมูลสองไม้ปะปนกัน และไม่ต้องรอการติดตามเสร็จก่อนเปิดไม้
- การนำข้อมูลเหล่านี้ไปปรับกฎภายหลังต้องเป็นงานวิเคราะห์และการเปลี่ยนเวอร์ชันที่ตรวจสอบได้ ไม่ใช่การปรับอัตโนมัติ

## 4. นิยามการวัดหลัง SL

- เริ่มที่เวลาตรวจพบ SL จริง จนถึงขอบปิด M5 ถัดไป เช่น 22:03 ถึง 22:05 ตามเวลาไทย
- ถ้า SL อยู่ตรงขอบเวลา M5 พอดี ให้ติดตามถึงขอบถัดไปและบันทึกขอบเวลาไว้อย่างชัดเจน
- ใช้เฉพาะราคาหลัง SL ห้ามใช้ High/Low ของทั้งแท่งที่รวมช่วงก่อน SL
- แยกเวลาเริ่มแท่งกับเวลาปิดแท่ง ใช้ epoch/UTC ภายใน แปลงเป็น Asia/Bangkok เพื่อแสดงผล
- ราคาอ้างอิง MFE/MAE คือราคาที่ตรวจพบตอนออก โดยวัดตามฝั่งของไม้เดิม
- กำหนด sign=+1 สำหรับ BUY, -1 สำหรับ SELL; delta=sign*(ราคาที่ใช้ปิดฝั่งเดิม-ราคาออกที่ตรวจพบ)
- MFE หลัง SL=max(0, delta สูงสุด); MAE หลัง SL=max(0, -delta ต่ำสุด)
- BUY ใช้ Bid; SELL ใช้ Ask สำหรับราคาที่ใช้ปิดฝั่งเดิม ห้ามแทน Ask ย้อนหลังด้วย Bid โดยไม่ระบุข้อจำกัด
- บันทึกการแตะ TP เดิมหลัง SL พร้อมเวลา และระบุว่าเป็นการแตะที่สังเกตพบ ไม่ใช่ยืนยันเส้นทางครบทุก tick
- บันทึกว่าราคาปิดกลับเข้าด้านใน SL เดิมหรือไม่ พร้อมเวลา/ชนิดราคา หากมีเพียง quote ใกล้ขอบเวลาให้แสดงว่าเป็น quote ใกล้เวลาปิด ไม่ใช่ราคาปิดที่ยืนยันแล้ว
- หากข้อมูลขาด ให้บันทึกสถานะข้อมูลไม่ครบและสิ่งที่สังเกตพบ ห้ามยืนยันว่าไม่แตะ TP หรือเป็นเพียงไส้เทียน
- ใช้ถ้อยคำว่าแตะแล้วกลับ หรือยังอยู่นอก SL ณ เวลาที่วัด ไม่ฟันธงว่าฝั่งผิดจริงจากแท่งเดียว

## 5. ทิศทางข้อมูลและความทนทาน

- ข้อมูลตลาดส่งให้ decision และ observer แยกกัน; decision ส่งสำเนาเหตุการณ์ให้ audit/research ทางเดียว
- observer ต้องไม่เขียนกลับ decision state; ไม่ใช้ dictionary ที่แก้ร่วมกัน
- แยกชื่อฟิลด์ เช่น trade.mfe_observed กับ post_sl.mfe_after_exit ไม่ใช้ mfe/mae เดียวกันคนละความหมาย
- บันทึก observer แบบทำซ้ำได้โดยไม่สร้างรายการซ้ำ และกู้สถานะติดตามที่ยังไม่จบหลังรีสตาร์ตได้
- ใช้คิว/งานบันทึกที่มีขอบเขต ไม่รอ sleep จนแท่งปิดในเส้นทางตัดสินใจ
- เมื่อ observer เกิดข้อผิดพลาดหรือคิวเต็ม ให้บันทึกความไม่ครบของงานวิจัย การตัดสินใจต้องทำงานต่อและสถานะไม่เปลี่ยนเพราะข้อผิดพลาดนี้

## 6. เกณฑ์ตรวจรับก่อนใช้จริง

- เมื่อเปิด/ปิดงาน audit และ post-SL โดยใช้ข้อมูลตลาดและการตั้งค่า decision เดียวกัน ผลเข้าออก/ราคา/TP/SL/cooldown ต้องเหมือนกันทุกจุด
- จำลอง observer error, restart และเหตุการณ์ซ้ำแล้ว decision ยังเหมือนเดิม
- ตรวจกรณี SL กลางแท่งเพื่อยืนยันว่าไม่ปนราคาก่อน SL และตรวจ BUY/Bid, SELL/Ask แยกกัน
- ทดสอบการแก้ setup ปฏิกิริยาค้างต่างหาก ไม่อ้างผลของงานเก็บข้อมูลว่าเพิ่มความสามารถเลือกฝั่ง
- บันทึกเวอร์ชัน decision และ research แยกกันให้ตรวจย้อนหลังได้

เอกสารนี้เป็นข้อกำหนดที่ต้องอ่านก่อนพัฒนา V3 ไม่ใช่หลักฐานว่าระบบที่รันจริงได้แยกส่วนและผ่านการทดสอบแล้ว
